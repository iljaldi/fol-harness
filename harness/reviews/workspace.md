# 파일럿 리뷰 — workspace (프로젝트 작업 공간)

> 작성일 2026-10-04 · 작성자 오케스트레이터 · r8-review.md 3~4절 기준

workspace는 규칙 A·B가 모두 걸리는 화면이라 파일럿으로 선정됐다 (r8-review.md 3절).
S1→S5를 두 바퀴 돌았다: 1차는 uibowl 레퍼런스로, 2차는 사용자가 "유아이볼 AI CoS" 제품
캡처를 보여주며 그 수준으로 다시 만들어달라고 해서 S1부터 전면 재실행했다. 이후 S5
결과물에 대한 수동 폴리싱 요청이 다섯 차례 있었다.

## 게이트별 FAIL 횟수

gates.json 기준 (2차 파이프라인, 최종 상태):

| 게이트 | result | totalFailures |
|---|---|---|
| G1 | PASS | 1 |
| G2 | PASS | 0 |
| G3 | PASS | 0 |
| G4 | PASS | 0 |
| G5 | PASS | 0 |
| G6 | PASS | 0 |

G1의 실패 1건은 1차 파이프라인 완료 후 사용자가 레퍼런스를 자체 제공 캡처로 교체하면서
발생했다 (아래 '오탐 FAIL' 참고). G6는 S5 폴리싱 5라운드(최초 제작 + 수동 수정 포함 6회
판정) 동안 매번 PASS를 유지했다 — rules.json 토큰 위반 없이 반복 수정이 가능했다.

## 잘못 걸린 FAIL (오탐) — 1건

- **G1 — uibowl 링크 필수 검사**: `check_g1`이 레퍼런스 `url`에 `"uibowl"` 문자열을
  하드 요구했다. 사용자가 uibowl 검색 결과 대신 자사 제품(유아이볼 AI CoS) 캡처를
  직접 제공하자 정당한 레퍼런스인데도 FAIL 처리됐다.
  - **조치**: `harness/gates/check.py`의 `check_g1`을 "uibowl 링크 또는 '사용자 제공'
    출처 표시 중 하나"로 완화 (커밋 `c5398f1`). 출처 추적 의무는 유지하면서 소스
    다양성을 허용.

## 걸렸어야 했는데 통과한 것 (놓침) — 게이트 기준 0건, 수동 발견 2건

G1~G6 판정 스크립트 기준으로는 놓친 사례가 없었다. 다만 S5 수동 수정 이후 동기화
과정에서, **게이트가 애초에 검사하지 않는 종류의 문제** 2건을 발견했다:

1. `workspace-default`와 `workspace-ai-rewrite-confirm` 두 프레임의 `SavedBadge`가
   서로 다른 크기·굵기로 벌어짐 (사용자가 한쪽 프레임만 수동 수정).
2. `workspace-empty`의 `StepRow_0`에 활성 강조 배경은 추가됐는데, 상태 점 색과 배지
   텍스트("미작성")가 그대로 남아 서로 모순된 상태로 보임.

두 건 모두 rules.json의 색·radius·spacing·폰트 허용값 안에서 벌어진 변경이라 G6가
구조적으로 잡을 수 없는 범주다(G6는 토큰 준수만 보지, **프레임 간 일관성**이나 **상태
표시 논리적 정합성**은 보지 않는다). 사람이 스크린샷을 비교해 발견했고, 사용자 확인 후
수동 수정했다.

- **향후 검토 과제**: G3(화면 설계) 또는 G6에 "동일 컴포넌트는 프레임 간 속성이
  같아야 한다" 류의 교차 프레임 일관성 검사를 추가할지는 다음 화면 진행 후 재논의.
  지금은 비용 대비 효과가 불확실해 보류.

## 내가(오케스트레이터) 직접 고친 횟수 — 2건

판정/보호 스크립트에 직접 손댄 것만 집계 (사용자가 Figma에서 수동으로 디자인을 고친
것은 별도 항목):

1. `harness/gates/check.py` — G1 uibowl 링크 요건 완화 (커밋 `c5398f1`)
2. `harness/hooks/guard.py` — `harness/reviews/` 경로를 보호 대상에서 제외 (커밋
   `db5d756`). r8-review.md가 설계한 "오케스트레이터가 리뷰를 정기적으로 쓴다"는
   흐름과 CLAUDE.md의 "harness/ 아래 전부 보호"가 충돌해서 발견됨.

참고로 `.claude/agents/ref-collector.md`의 uibowl 도구 이름 오타
(`mcp__claude_ai_uibowl__*` → `mcp__uibowl__*`)도 1차 S1 실행에서 발견됐지만, 이건
**사용자가 직접** 수정했다 (오케스트레이터가 고친 건수에는 포함하지 않음).

## 기존 시안과의 차이

workspace는 이 하네스로 만든 첫 화면이라 비교할 기존 완성 시안이 없다. 해당 없음.

## 기타 메모

- 가짜 소스 방지(규칙 B): 사용자 제공 레퍼런스를 쓸 때 ref-collector가 uibowl 링크를
  꾸며내지 않고 "사용자 제공 캡처"로 출처를 명시한 점은 규칙 B 설계 의도대로 동작했다.
- uibowl 검색 자체에서도 비슷한 패턴이 있었다: "채널톡"이 uibowl에 독립 화면으로
  없다는 걸 확인하고도 억지로 채우지 않고, 위젯이 실제로 보이는 다른 서비스 화면을
  대안으로 쓰며 그 사실을 보고에 명시했다 (가짜 레퍼런스 생성 없음).
- 훅 오탐 1건: `cp` 명령이 프로젝트 폴더명 "fol-harness"에 포함된 "harness" 문자열
  때문에 guard에 두 차례 막혔다 (ref-collector 보고). 이번엔 상대경로로 우회해 작업엔
  지장 없었지만, `PROTECTED_MARKS`의 `"harness/"` 매칭이 디렉터리명 전체를 보지 않고
  부분 문자열로 걸리는 구조적 약점이다. 다음 화면에서 또 걸리면 패턴을 경로 기준으로
  다듬는 걸 검토한다.
